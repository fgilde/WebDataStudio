# P7 — Tier 2 and Tier 3 Engines Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add Oracle, DuckDB and ClickHouse behind the existing SQL interface, and MongoDB and Redis behind a non-SQL variant of it — proving the abstraction holds.

**Architecture:** Tier 2 engines are ordinary `AdoDriverBase` implementations with reduced capability sets; they must pass the same contract suite. Tier 3 declares `Caps.Sql = false`, which switches three things and nothing else: the editor language, the execution request shape and the result renderer. Connections, history, export and the shell stay identical.

**Tech Stack:** Oracle.ManagedDataAccess.Core, DuckDB.NET.Data.Full, ClickHouse.Client, MongoDB.Driver, StackExchange.Redis, Testcontainers.

**Spec:** `docs/superpowers/specs/2026-08-18-webdatastudio-design.md`

## Global Constraints

- Everything from P0–P6 global constraints still holds.
- A tier-2 driver is done when it passes `DriverContractTests` and `CapabilityHonestyTests` for the capabilities it claims. No exceptions to the suite, no engine-specific skips beyond the capability gates the suite already honours.
- Tier 3 must not weaken the SQL path. If a shared component needs a change to accommodate a document store, the change must keep the SQL behaviour byte-identical, asserted by re-running the tier-1 suites.
- Feature IDs delivered by this phase: F14.1–F14.3, plus capability extensions across F2, F4, F5 and F7 for the new engines.

**Files:**
- Create: `src/WebDataStudio.Server/Drivers/Oracle/OracleDialect.cs`, `OracleDriver.cs`
- Create: `tests/WebDataStudio.Server.Tests/Drivers/OracleFixture.cs`
- Modify: `Directory.Packages.props`, `DriverRegistry`

**Interfaces:**
- Produces: `OracleDriver` registered under `oracle`.

- [ ] **Step 1: Write the fixture and contract subclass**

`Testcontainers.Oracle` with `gvenzl/oracle-free:slim`, seeding the same `people` and `orders` tables
the other fixtures use (Oracle spelling: `NUMBER GENERATED BY DEFAULT AS IDENTITY`, `VARCHAR2(100)`,
`NUMBER(1)` for the boolean). Add `public class OracleContractTests(OracleFixture f) : DriverContractTests<OracleFixture>(f);`.

- [ ] **Step 2: Run it to verify it fails**

Run: `dotnet test --filter OracleContract`

- [ ] **Step 3: Write the dialect**

Double-quoted identifiers, `:` parameter prefix, `OFFSET n ROWS FETCH NEXT m ROWS ONLY` paging, and
an `IsReadOnlyStatement` override that also treats `BEGIN` blocks as writes. Oracle folds unquoted
identifiers to upper case — the dialect exposes `NormalizeIdentifier` so introspection and the
designer agree on casing.

- [ ] **Step 4: Write the driver**

Introspection from `all_users` (schemas), `all_tables`, `all_views`, `all_procedures`, `all_sequences`,
`all_tab_columns`, `all_indexes` with `all_ind_columns`, and `all_constraints` joined to
`all_cons_columns` for keys. Plans via `EXPLAIN PLAN FOR` plus a read from `PLAN_TABLE`, mapped into
`PlanNode`. Capabilities: everything except `PartialIndexes` and `IncludeColumns`.

- [ ] **Step 5: Run the suite and commit**

```bash
dotnet test --filter "OracleContract|CapabilityHonesty"
git add -A && git commit -m "feat: Oracle driver"
```

### Task 3: ClickHouse driver

**Files:**
- Create: `src/WebDataStudio.Server/Drivers/ClickHouse/ClickHouseDialect.cs`, `ClickHouseDriver.cs`
- Create: `tests/WebDataStudio.Server.Tests/Drivers/ClickHouseFixture.cs`

**Interfaces:**
- Produces: `ClickHouseDriver` registered under `clickhouse`.

- [ ] **Step 1: Write the fixture**

`Testcontainers.ClickHouse`, seeding `people` and `orders` as `MergeTree` tables ordered by `id`.
ClickHouse has no real foreign keys, so the fixture creates the column without a constraint and the
contract suite skips the foreign-key assertion via `Caps.ForeignKeys = false` — exactly the mechanism
the capability gates exist for.

- [ ] **Step 2: Implement**

Backtick-or-double-quote identifiers, `LIMIT n OFFSET m` paging, catalogue from `system.databases`,
`system.tables`, `system.columns`, and `system.data_skipping_indices`. Plans via
`EXPLAIN PLAN indexes = 1` parsed by indentation. Capabilities: no `ForeignKeys`, no `Triggers`,
no `Transactions`; `SystemCommands` on (OPTIMIZE, ATTACH, DETACH), `ServerStats` on via
`system.metrics`.

- [ ] **Step 3: Handle the no-transaction case**

`AdoDriverBase` already runs statements without an explicit transaction. Assert in the contract suite
that the P4 apply path returns a clear "this engine has no transactions; changes apply one by one"
message rather than silently pretending atomicity.

- [ ] **Step 4: Run the suite and commit**

```bash
dotnet test --filter "ClickHouseContract|CapabilityHonesty"
git add -A && git commit -m "feat: ClickHouse driver"
```

### Task 5: MongoDB driver

**Files:**
- Create: `src/WebDataStudio.Server/Drivers/MongoDb/MongoDbDriver.cs`, `MongoCommandParser.cs`
- Create: `tests/WebDataStudio.Server.Tests/Drivers/MongoDbFixture.cs`
- Create: `tests/WebDataStudio.Server.Tests/Drivers/MongoCommandParserTests.cs`

**Interfaces:**
- Produces:
  - `MongoCommandParser.Parse(string text) -> MongoCommand` with `record MongoCommand(string Collection, string Operation, BsonDocument[] Arguments)` supporting `db.coll.find({…})`, `.findOne`, `.aggregate([…])`, `.countDocuments`, `.insertOne`, `.insertMany`, `.updateOne`, `.updateMany`, `.deleteOne`, `.deleteMany`, `.createIndex`, `.getIndexes`, `.drop`.
  - `MongoDbDriver` registered under `mongodb` with `Caps.Sql = false`.

- [ ] **Step 1: Write the parser tests**

Assert: `db.people.find({ active: true })` parses to collection `people`, operation `find`, one
argument; relaxed JSON (unquoted keys, single quotes, trailing commas) parses; an aggregation pipeline
parses to an array argument; `db.people.find({}).limit(10)` carries the limit; an unknown operation
throws `NotSupportedException` naming it; a write operation is classified as a write so a read-only
connection can refuse it.

- [ ] **Step 2: Write the fixture and contract subclass**

`Testcontainers.MongoDb`, seeding a `people` collection with the same three documents and an `orders`
collection. A dedicated `MongoContractTests` runs the subset of the contract suite the capabilities
allow — the suite's existing capability gates handle the rest.

- [ ] **Step 3: Implement the driver**

Introspection: databases, then collections, then indexes; `DescribeAsync` infers a document shape by
sampling 100 documents and reporting the observed field names and their BSON types as `ColumnInfo`,
with a comment that this is a sample, not a schema. Execution streams documents in batches of 200 as
`ResultChunk.Documents`. `ExplainAsync` maps `db.coll.find(...).explain("executionStats")` into
`PlanNode` (`COLLSCAN` becomes a warning, `IXSCAN` does not).

- [ ] **Step 4: Run the suites and commit**

```bash

git add -A && git commit -m "feat: MongoDB driver"
```

**Interfaces:**

- [ ] **Step 1: Write the fixture and tests**

`Testcontainers.Redis`, seeded with one string, one hash, one list, one set and one sorted set.
Assert: the tree groups keys by their `:` prefix into folders; a key node reports its type and TTL;

enforcement uses an allow-list of read commands rather than the SQL dialect classifier — that is what
`Caps.Sql = false` buys.

## Phase exit criteria

- Oracle, DuckDB and ClickHouse pass the full contract suite for their declared capabilities.
- MongoDB and Redis browse, query, edit and export; their tabs use the document renderer.
- Re-running the tier-1 suites after the tier-3 work shows no behaviour change.
- The UI hides every unsupported feature per engine — no dead buttons anywhere.
- The README capability matrix matches `GET /api/drivers`.
- Feature IDs F14.1–F14.3 are demonstrably working, and F2/F4/F5/F7 hold for all nine engines.
