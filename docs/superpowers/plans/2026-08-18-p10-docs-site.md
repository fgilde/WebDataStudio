# P10 — Bilingual Documentation Site Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A GitHub Pages site under `/docs` documenting the whole tool in English and German, looking like the AspireUI docs, linked from the README and back to the repository and the image.

**Architecture:** docsify, served straight from `/docs` on the default branch — no build step, no generator. English pages live at the root of `/docs`, German pages mirror them under `/docs/de/` with their own `_sidebar.md`, which is docsify's own i18n mechanism.

**Tech Stack:** docsify 4 from a CDN, the AspireUI docs stylesheet, Playwright for the screenshots.

**Spec:** `docs/superpowers/specs/2026-08-18-webdatastudio-design.md`

## Global Constraints

- The reference implementation is `C:\dev\privat\github\AspireUI\docs` — same docsify setup, same visual language, brand colour adjusted to WebDataStudio.
- Every English page has a German counterpart at the same relative path under `/docs/de/`. A page that exists in one language and not the other is a build failure, enforced by the link check.
- The site documents behaviour that exists. A feature still in an unfinished phase is either absent or explicitly marked as planned.
- `/docs/superpowers/` (specs and plans) stays out of the site navigation — it is developer material, not user documentation.
- Feature IDs delivered by this phase: F15.1–F15.6.

### Task 1: Site skeleton

**Files:**
- Create: `docs/index.html`, `docs/README.md`, `docs/_sidebar.md`, `docs/.nojekyll`
- Create: `docs/de/README.md`, `docs/de/_sidebar.md`
- Create: `docs/webdatastudio.svg` (logo)

**Interfaces:**
- Produces: a docsify site whose language switch flips between `/` and `/de/`.

- [ ] **Step 1: Copy and adapt the AspireUI shell**

Copy `AspireUI/docs/index.html`, then change: the title and description, the brand colour tokens to the
WebDataStudio accent, the logo reference, and add the docsify i18n config:

```js
window.$docsify = {
  name: 'WebDataStudio',
  repo: 'https://github.com/fgilde/WebDataStudio',
  loadSidebar: true,
  subMaxLevel: 2,
  fallbackLanguages: ['de'],
  search: { paths: 'auto', placeholder: { '/de/': 'Suchen', '/': 'Search' } },
};
```

- [ ] **Step 2: Add the language switch**

A two-item link list at the top of both sidebars — `[English](/) · [Deutsch](/de/)` — so a reader can
flip without hunting for a menu.

- [ ] **Step 3: Write both landing pages**

`docs/README.md` and `docs/de/README.md`: what the tool is, the `docker run` one-liner, the supported
engines table, and a link to Getting Started. Not a translation exercise for its own sake — the German
page reads as German, not as translated English.

- [ ] **Step 4: Verify locally**

```bash
npx docsify-cli serve docs
```

Expected: both languages render, the sidebar switch works, no 404 in the console.

- [ ] **Step 5: Commit**

```bash
git add -A && git commit -m "docs: docsify site skeleton in English and German"
```

### Task 2: Content pages

**Files:**
- Create in both `docs/` and `docs/de/`: `getting-started.md`, `connections.md`, `query-editor.md`, `results-and-export.md`, `schema-editing.md`, `analysis.md`, `administration.md`, `engines.md`, `shortcuts.md`, `configuration.md`

**Interfaces:**
- Consumes: the feature inventory from the spec and `docs/features.md` from P9.
- Produces: the pages listed in both sidebars.

- [ ] **Step 1: Write the English pages**

One page per area, each answering: what it does, how to reach it, what differs per engine. The
`configuration.md` page carries the environment variable table verbatim from the spec — one source of
truth, copied deliberately rather than paraphrased.

- [ ] **Step 2: Write the German pages**

Same structure, same anchors, German prose. Technical terms, SQL keywords, environment variable names
and CLI commands stay in their original form.

- [ ] **Step 3: Generate the engine capability matrix**

A script reads `GET /api/drivers` from a locally running container and writes the matrix into both
`engines.md` files between marker comments, so the table cannot drift from the code.

- [ ] **Step 4: Commit**

```bash
git add -A && git commit -m "docs: content pages in English and German"
```

### Task 4: Publishing and link check

**Files:**
- Create: `.github/workflows/docs.yml`
- Modify: `README.md`

**Interfaces:**
- Produces: the published site and a CI job that fails on a broken internal link.

- [ ] **Step 1: Enable Pages**

Repository settings: Pages from the default branch, `/docs` folder. `.nojekyll` is already in place so
docsify's underscore-prefixed files are served.

- [ ] **Step 2: Write the link check**

A workflow step that walks every Markdown file under `docs/` (excluding `docs/superpowers/`), extracts
relative links and image references, and fails when a target does not exist. Also fails when an English
page has no German counterpart, and vice versa.

- [ ] **Step 3: Link from the README**

A documentation line near the top: **Documentation: [English](https://fgilde.github.io/WebDataStudio/) ·
[Deutsch](https://fgilde.github.io/WebDataStudio/#/de/)**.

- [ ] **Step 4: Verify the published site**

After the first push, open both URLs and click through every sidebar entry.

- [ ] **Step 5: Commit**

```bash
git add -A && git commit -m "ci: publish docs site and check links"
```

## Phase exit criteria

- The site is live on GitHub Pages and reachable in both languages.
- Every sidebar entry resolves; the link check passes in CI.
- Every English page has a German counterpart and the switch works from any page.
- The engine capability matrix on the site matches `GET /api/drivers`.
- The README links to both languages, and the site links back to the repository and the GHCR image.
- Feature IDs F15.1–F15.6 are demonstrably working.
